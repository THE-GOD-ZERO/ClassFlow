## 目前限制与风险

1. 当前仍是第一阶段基础工程，没有课程录入、Today、Schedule 或 Settings 界面，不能当成已可日用的课表 App。
2. 日历解析只是基础语法；只处理全天事件，不下载官方节假日数据库，不猜调休对应的学校课表。实际校历文本差异需在第五阶段结合用户来源验证。
3. 待确认调休日提供普通星期课程预览；后续 Today 必须明确提示，通知必须跳过待确认/冲突结果。
4. 同步目前在主线程串行进行，范围限制为一个学期（最多 104 周）。很大的日历需要真机性能测量，必要时迁移读取/解析到独立执行上下文。
5. 事件提供方的本地标识在账户重建/重新订阅时可能变化；旧自动记录会被清理，新的记录可能需要再次确认。相同标识但正文变更也会使映射重新确认。
6. 学校安排若要求替换“教学周”而不只是“星期”，当前模型不会自动支持；这是未来显式功能扩展。
7. 无后台常驻同步、通知滚动排程、备份、iCloud、Widget。没有 App Group 或网络服务器。
8. Schema V1 的迁移设计、SwiftData 唯一约束与将来的 CloudKit 兼容性仍需在引入新能力时专门处理。
